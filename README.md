# 一人公司工作台 · Solo Workbench

> 给「一个人的公司」用的单文件工作台。没有账号、没有后端、没有构建步骤 —— 双击 HTML 就能用。
>
> 一个页面装下六件事：长期主线推进、AI 资讯、抖音热榜选题、学习沉淀、喝水打卡、记账理财。

---

## 它是什么

一个人做公司，真正难的不是某件事做不完，而是**主线、灵感、现金流、身体这几件事同时散落在脑子里的不同角落**。这个工作台把它们收进一个页面，并且遵守三条硬约束：

| 约束 | 具体表现 |
|---|---|
| **零依赖** | 单个 HTML 文件，CSS / JS / 图标 / 图表全部内联。不引任何 CDN、框架、字体、图表库，断网照常运行，把文件拷到 U 盘也能用 |
| **零后端** | 没有服务器、没有数据库、没有账号。数据存在浏览器 `localStorage`，换设备靠导出 JSON 迁移 |
| **零维护** | 不需要 `npm install`，不需要跑构建。改完文件刷新浏览器即可 |

图表全部是手写内联 SVG（进度环、柱状图、饼图、周节奏），图标全部是内联 SVG path，没有 emoji。

## 快速开始

### 方式一：最省事（推荐先试这个）

1. 下载仓库里的 `solo-workbench.html`
2. 双击，用浏览器打开
3. 开始用

不需要服务器，不需要装任何东西。

### 方式二：当 App 装到手机（PWA 版）

`solo-pwa/` 是同一套页面 + 安装清单 + 离线缓存，**安卓 Chrome 可以安装成桌面图标，全屏无地址栏、断网也能打开**。

```bash
# 本地起个静态服务（PWA 的 Service Worker 必须走 http/https，不能直接双击 file://）
cd solo-pwa
python3 -m http.server 8000
# 浏览器打开 http://localhost:8000
```

手机上操作：用 **Chrome** 打开地址 → 右上角菜单 → **「安装应用」**（没有这项就点「添加到主屏幕」）。

> 注意：在微信内置浏览器里打不开这功能，要先点右上角 `⋯` → 「在浏览器打开」。
> 想获得公网链接，把 `solo-pwa/` 推到 GitHub Pages 即可（Pages 自带 HTTPS，PWA 能正常安装）。

### 环境要求

- 现代浏览器：Chrome / Edge / Safari / Firefox 近两年版本
- 浏览器需允许 `localStorage`（无痕模式下部分浏览器会禁写，数据将不持久）
- 无 Node / Python 运行时要求（只是可选地用来起本地服务）

## 六个模块：输入什么、输出什么

### 1. 长期工作 + 今日总览

左栏（手机上是顶部）是长期主线，主区顶部是「今天要处理」。

**输入**

| 字段 | 必填 | 说明 |
|---|---|---|
| 长期工作 · 名称 | ✅ | 一条主线，如「接单交付主业」 |
| 长期工作 · 目标 | ❌ | 一句话，如「本月完成 5 单」 |
| 里程碑 · 任务 | ✅ | 具体动作，如「完成客户提案初稿」 |
| 里程碑 · 截止日期 | ❌ | `YYYY-MM-DD`，默认今天 |

**输出与规则**

- **逾期**：未完成 且 截止日 < 今天 → 红色标注 + 显示逾期天数，并**自动出现在「今天要处理」**，不会因为日期过去而消失
- **今日待办**：截止日 = 今天 且 未完成
- **进度**：已完成里程碑数 / 总里程碑数，显示为进度条
- 每条逾期/待办项给一个一键完成按钮

---

### 2. AI 资讯

**输入**：点右上角「更新资讯」，支持两种格式。

**格式 A —— 竖线分隔文本**（一行一条）

```
标题 | 关键信息 | 一句话摘要
模型发布 | 某模型 API 降价 40% | 官方宣布长文本场景成本减半
```

分隔符用半角 `|` 或全角 `｜` 都可以，两端空格自动去除。

**格式 B —— JSON**（数组，或 `{"items": [...]}`）

```json
[{ "tag": "模型发布", "title": "某模型发布", "sum": "摘要", "why": "一人公司怎么用" }]
```

**解析规则（重要）**

- 每行至少要有 2 段，否则该行被跳过
- 缺 `title` 的条目直接丢弃
- `tag` 缺省时自动补 `资讯`
- JSON 解析失败会**自动回退**到文本按行解析
- 首字符是 `[` 或 `{` 时优先按 JSON 解析

**输出**

- 列表渲染：`标签 · 标题 · 摘要 · 关键信息`
- 「存为选题」→ 写入选题库 `{title: 资讯标题, note: 关键信息, from: "AI 资讯"}`
- 「转待办」→ 往**第一个**长期工作追加一条里程碑，截止日 = 明天

---

### 3. 抖音热榜与选题

**输入**：点右上角「更新热榜」。

**格式 A —— 竖线分隔文本**（一行一条）

```
排名 | 热点标题 | 契合选题 | 切入角度
1 | 某某热点事件 | 《一人公司如何借这个热点做内容》 | 从个人经历切入，给出可复用模板
```

**格式 B —— JSON**：字段 `rank` / `title` / `topic` / `angle`，规则同上。

**解析规则**

- `rank` 不是数字时，按出现的行序自动编号（1、2、3…）
- `cat` 缺省时补 `热点`
- 其余与 AI 资讯一致（缺 `title` 丢弃、JSON 失败回退文本）

**输出**

- 列表渲染：`排名 · 分类 · 热点标题 · 契合选题 · 切入角度`
- 「存为选题」→ 标题**优先取 `topic` 字段**，`topic` 为空时才用 `title`；`note` 取 `angle`；`from: "抖音热榜"`

---

### 4. 已学习

两级结构，**都能无限叠加**。

**模块** = 一个学习主题（如「AI 工具与工作流」）。可新增、重命名、删除、上下移动顺序、折叠收起。
**内容块** = 模块里的内容单元，一个模块可叠任意多个、任意多种，顺序随时可调。

**内容块 6 种类型与校验条件**

| 类型 | 输入字段 | 校验规则 |
|---|---|---|
| 文本笔记 | 小标题（选填）、内容 | 标题与内容**同时为空时拒绝保存** |
| 要点清单 | 小标题、多行要点（一行一条） | 至少 1 条，空行忽略；已勾选状态按**行序**对应保留（改完后行序变动会错位，属预期行为） |
| 链接收藏 | 小标题、URL | URL 必填；不以 `http(s)://` 开头时**自动补 `https://`** |
| 代码·提示词 | 小标题、代码/prompt | 内容不能为空，等宽字体展示 |
| 金句摘录 | 小标题、摘录内容、出处 | 摘录内容必填，出处选填 |
| 图片 | 小标题、图片文件 | 单文件 < 12MB，自动压缩到 **800px 宽**后转 base64 存储 |

**输出**

- 顶部四张统计卡：模块数、内容块总数、要点掌握进度（已勾选 / 总数）、最近更新日期
- 清单项可逐条勾选标记「已掌握」
- 「+ 加入复习待办」→ 往**第一个**长期工作追加 `复习：<模块名>`，截止日 = 3 天后

### 5. 喝水打卡

**输入**

| 操作 | 效果 |
|---|---|
| 「+1 杯」 | 今日杯数 +1，记录当前时间 `HH:MM` 为上次喝水时间 |
| 「撤销一杯」 | 今日杯数 −1，最低到 0；今天没记录时提示「今天还没有记录」 |
| 每日目标 | 1–20 杯。非法或 ≤ 0 → 回落为 **8**；> 20 → 截断为 **20** |
| 提醒间隔 | 15–240 分钟。< 15 → 回落为 **45**；> 240 → 截断为 **240** |

**输出**

- 进度环（今日杯数 / 目标）、杯子格子、近 7 天柱状图
- 达成目标时提示「今日喝水目标达成」

**提醒触发条件（四条必须同时满足）**

1. 当前停留在**喝水打卡这一页**（切到别的板块不弹）
2. 今日杯数 **<** 每日目标
3. 当前时间 **晚于** 稍后提醒截止时间
4. 今天还没喝过 **或** 距上次喝水 ≥ 提醒间隔

每 **60 秒**检查一次。这是**页面内提示条，不是系统通知** —— 浏览器必须保持打开状态才会响。
点「喝了」= 记一杯并把稍后状态清零；点「稍后」= 20 分钟后再提醒。

### 6. 记账理财

**输入**

| 字段 | 必填 | 规则 |
|---|---|---|
| 类型 | ✅ | 支出 / 收入，默认**支出** |
| 金额 | ✅ | 必须 > 0，自动保留两位小数（四舍五入） |
| 日期 | ❌ | 默认今天 |
| 分类 | ✅ | 从预设分类里选（见下） |
| 备注 | ❌ | 自由文本 |
| 月预算 | ❌ | 任意正数；按月记录，跨月自动沿用金额 |

- 支出分类：`工具订阅 / 外包协作 / 设备采购 / 内容推广 / 差旅交通 / 餐饮 / 房租水电 / 其他`
- 收入分类：`接单交付 / 咨询服务 / 课程售卖 / 广告分成 / 平台补贴 / 其他`

**输出**

- **支出红色、收入绿色**（国内习惯，与欧美配色相反），货币符号 `¥`
- 月预算进度条、本月支出分类饼图（8 色循环）、近 6 个月收支双柱对比
- 流水明细列表，可单条删除

**CSV 导出规格**

- 文件名：`流水明细-YYYY-MM-DD.csv`
- 列顺序：`日期,类型,分类,备注,金额`
- 类型列取值：`支出` / `收入`
- **支出金额带负号**（如 `-168`），收入为正数
- 按日期倒序排列
- 编码 UTF-8 **带 BOM**（Excel 直接打开不乱码）
- 字段用双引号包裹，字段内的双引号转义为两个双引号

## 数据存储与备份

### localStorage 键位

所有 key 统一 `wb_solo_` 前缀，避免与其它页面冲突。

| Key | 内容 | 结构 |
|---|---|---|
| `wb_solo_projects` | 长期工作与里程碑 | `[{id, name, goal, milestones:[{id, title, due, done}]}]` |
| `wb_solo_water` | 每日喝水 | `{"YYYY-MM-DD": {cups: number, last: "HH:MM"}}` |
| `wb_solo_ledger` | 收支流水 | `[{id, date, type:"in"\|"out", amount, cat, note}]` |
| `wb_solo_budget` | 月预算 | `{month: "YYYY-MM", amount}` |
| `wb_solo_topics` | 选题库 | `[{id, title, note, from, date}]` |
| `wb_solo_settings` | 喝水设置 | `{goal, gap, lastDrink: ISO, snoozeUntil: 毫秒时间戳}` |
| `wb_solo_news` | AI 资讯 | `{stamp, items:[{id, tag, title, sum, why}]}` |
| `wb_solo_hot` | 抖音热榜 | `{stamp, items:[{id, rank, title, cat, topic, angle}]}` |
| `wb_solo_learn` | 已学习 | `[{id, name, desc, blocks:[...], collapsed, createdAt, updatedAt}]` |
| `wb_solo_seeded` / `wb_solo_seeded2` | 初始化与一次性迁移标记 | `boolean` |

### 导出 JSON

文件名 `一人公司工作台备份-YYYY-MM-DD.json`：

```json
{
  "_app": "solo-workbench",
  "_version": 1,
  "_exportedAt": "2026-09-08T05:34:00.000Z",
  "projects": [], "water": {}, "ledger": [],
  "budget": {}, "topics": [], "settings": {},
  "news": {}, "hot": {}, "learn": []
}
```

### 导入恢复

- 支持粘贴 JSON 文本，或选择 `.json` 文件
- **只覆盖 JSON 里出现的字段**，缺失的字段保留当前值（可以只导一部分数据）
- 没有条数上限，上千条也能导入
- 解析失败会提示「解析失败，请检查 JSON 格式」，不会破坏现有数据

### 清空数据

需要**两次确认**。确认后删除全部 `wb_solo_*` 键，并**重置为初始示例状态**（不是空白页）：

- 长期工作：空（由你自己填）
- 已学习：空
- 喝水：前 2 天 + 今天各若干杯
- 流水：5 条示例
- 预算：6000
- AI 资讯：7 条 / 抖音热榜：8 条

## 已知道的边界

说在前面，避免踩坑：

1. **数据只在这一个浏览器里**。换设备、换浏览器、换域名都不互通，只能靠导出 JSON 迁移。清理浏览器数据会一并清掉。
2. **没有系统通知**。喝水提醒是页面内提示条，浏览器关掉或切到别的标签页就不会响。这是刻意不做后端推送的代价。
3. **AI 资讯与抖音热榜是 2026-09-03 的静态快照**。页面本身不联网抓取，想要最新数据请用板块右上角的「更新资讯 / 更新热榜」手动粘贴，或后续接自己的数据源。
4. **localStorage 有容量上限**（通常约 5MB）。「已学习」里的图片是 base64 存的，图片多时注意空间；存满时页面会提示「保存失败：浏览器存储空间不足」。
5. **首次打开不是空白页**，会带一批示例数据（含流水和资讯），方便你先看清长什么样，不需要就点「清空数据」。
6. **长期工作为空时**，「转待办」「加入复习待办」会提示先在左侧创建一条长期工作 —— 这两个动作固定落到**第一个**长期工作上。

## 开发说明

改代码很简单，没有构建步骤：编辑 `solo-workbench.html` → 保存 → 刷新浏览器。

**架构上有一条铁律**：渲染函数之间不允许互相调用。所有联动统一走 `refreshAll()` 入口，按固定顺序调度 10 个渲染函数。历史上出现过「日历渲染」与「当天列表渲染」互相调用导致栈溢出的 bug，这类问题语法检查拦不住，所以从架构上杜绝：

```
用户交互 → 修改数据 → save() → refreshAll() → 各渲染函数独立读最新数据重绘
```

- **数据层**：`load(key, def)` / `save(key, val)`，统一 JSON 序列化
- **计算层**：`overdueList()` / `todayList()` / `learnStats()` 等纯函数
- **渲染层**：`renderXxx()` 只读 state 写 DOM，彼此不调用

改动 PWA 版本时，记得同步更新 `solo-pwa/sw.js` 里的 `CACHE` 版本号（如 `solo-workbench-v2`），否则用户端会一直用旧缓存。
